目的
PDF抽出ツールと日経マップの画像取り込みを修復する。生成済み5枚を再生成せず取り込み、正しい記事へ画像と起承転結説明を保存し、次の未処理5記事へ進めること。

最初に読むこと
このZIPは修正済み公開物ではなく、iCloudマスターの未完成コードと調査資料のスナップショット。Web版への移行のために作成した。今回の移行作業では本番へ反映していない。
GitHubのコードがこのスナップショットと同じかは未確認。上書きせず差分を確認すること。

対象
GitHub: https://github.com/mitsu43/pdf-extractor-tool
抽出ツール: https://mitsu43.github.io/pdf-extractor-tool/
日経マップ: https://nikkei-map.pages.dev/
ローカルマスター: iCloud Drive/news1共通
同梱の source/pdf-extractor-tool と source/gemini-map-import-extension が調査時のマスター。日経マップ全体のソースは同梱していない。

変更禁止の条件
・画像生成APIは使わない。GeminiチャットUIと既存Chrome拡張を使う。
・PDF分割は5ページ単位。画像生成5記事単位とは別の条件。
・1記事につき独立画像1枚。5記事を1画像にまとめない。
・縦4コマ、短い日本語見出し・セリフ、起承転結説明。
・生成済み画像、記事JSON、進捗、既存の公開データを消さない。
・利用者へ再抽出や再生成を安易に求めない。
・iCloudマスターを勝手に別の保存場所へ変更しない。クラウドでの変更はレビュー可能な差分として渡し、マスターへの反映状況を別途記録。
・内部テスト成功と、Gemini実画面のE2E成功を区別する。

今回確認した事実
1. マスターの拡張 manifest.json は version 1.4.3 / version_name に2026-10-11.8を含む。
2. 同じマスターの figure-gemini-bridge.js は step() で1.4.2だけを受け付ける。open/requestも1.4.3を許可していない。版の不整合をソースで確認した。まだ修正していない。
3. 利用者のブラウザで表示されたツールは v2026.10.11.7。
4. 画面の「続きから再開」で51記事を復元し、「今回JSON」で 20261010e_extracted.json をダウンロードした。記事JSONの退避のみであり、IndexedDB・拡張ストレージ・全画像の完全バックアップではない。記事データ自体は本ZIPに含めない。
5. figure-sequence.js にIndexedDBのキュー保存は存在する。Gemini指示書の「永続化が存在しない」「固定offset=0が原因」という断定はコード調査前の仮説であり、事実として採用しない。
6. 現在のキューキーは記事全文JSONとテーマのハッシュ。記事内容の変化で別キューが作成され得る。手動取り込みのfigureAssignmentsはメモリ上の配列で、復元の不足を調査する必要がある。
7. collector.mjs にはARTICLE_ID入り画像altからの照合、明示IMAGE_INDEX対応表の照合を追加した作業が残っている。実ブラウザでこの版が動いていることは未確認。
8. 現在の生成済み5枚の救出、次の5件選択、本番表示は未達。完了と報告しない。

優先する調査・実装
・拡張とWebツールの互換性確認を一元化し、実行中の版・拡張識別を表示する。複数拡張からの重複応答も調査。
・既存会話の送信済みジョブを読み取りで復元し、不明なときに自動再送しない。
・記事ごとの取得済み画像と説明をIndexedDBへ保存し、再読み込みで復元する。既存キューを移行せず破棄しない。
・画像取得、記事照合、ローカル保存、サイト保存を別々に検証する。ローカル保存を本番保存成功と呼ばない。
・部分取得は保持。不足分が生成済みか未生成かを確認してから続行する。
・生成済み画像は記事ID・正式タイトルなどで照合。順番だけで強制割り当てしない。
・PDF分割の既存実装をまずテストし、必要な範囲だけ修正する。

Gemini指示書の注意点
review.txt は利用者提供の技術レビュー全文。方針と検証ゲートは参考になるが、根本原因の断定やサンプルコードは未検証。
「最後の5画像を先頭5記事へ順番に割り当てて強制COMMITTED」は誤登録の危険があるため採用しない。
localStorage/sessionStorageだけの退避では既存IndexedDBのキューや画像を保全できない。
生成待ちや取得待ちを全て「未COMMITTED」として新規生成へ回すと重複生成になる。再開処理を状態別に分ける。
ログイン先への追加権限を安易に与えない。manifestには既にGeminiのhost_permissionsが存在する。
Canvas変換が必ず成功するとは限らない。CORS、画像読込状態、対象画像の識別を確認する。

検証ゲート
Gate 1: 実PDF27ページを分割し、生成されたPDFを再読込して[5,5,5,5,5,2]を確認。
Gate 2: 既存5枚を再生成せず、正しい記事へ画像・説明を保存し、実際の表示を確認。
Gate 3: 完了5記事を除き、6〜10件目が選ばれることを確認。リロード後も同様。
Gate 4: 次の5記事を1回の指示で生成し、取り込み・保存・表示まで確認。
クラウドからMacのログイン済みChromeを操作できない場合、Gate 2〜4を完了扱いにしない。ローカル検証が必要な範囲を具体的に残す。

同梱テスト
tests/ は既存テスト。絶対パスを同梱sourceへの相対参照へ機械的に変更した。モックテストをE2E証拠にしない。
Node.js 22以上を推奨。PDFテストはpdf-libが必要。
node tests/test-auto-continue.mjs
node tests/test-partial-collector.mjs
node tests/test-bulk-background.mjs
node tests/test-publication-five-pages.mjs
テストが失敗する場合は失敗内容を記録し、無理にアサーションを削除しない。
