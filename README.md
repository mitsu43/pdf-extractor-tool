# 保存・再開の修正（v2026.10.25.1）

- 「続きから再開」で保存済みの記事・スキーマ・手動バッチの進捗を復元し、抽出結果へ自動移動する。
- 元と同じ名前・ページ数のPDFを再選択しても記事を初期化せず、その進捗から続行する。
- 旧形式の保存は記事を保持して復元し、保存されていないバッチ完了状態は推測しない。
- 「破棄して新規開始」は画面内の確認を経て、IndexedDBの消去トランザクション完了後に新規画面へ戻る。失敗時は保存データと案内を残し、再試行できる。
- 生成APIの呼び出し・R2公開・既存の画像保存には変更を加えない。
- 検証: `node --test tests/test-session-restore.mjs tests/test-viewpoint-classification.mjs`。開発依存は `npm install --ignore-scripts --no-package-lock` で準備する。

# 全記事の一括生成・自動取込 (v2026.10.10.4)

1. 「Gemini手動連携はPDF全体を1回で抽出」をONにして抽出する。JSONが途中までの場合は取り込んだ後「指示文コピー」を押し、同じGemini会話へ続行指示を送る。既出記事は保持される。
2. 日付・版を確認し「全記事を一括生成・自動取込」を押す。記事の確定は自動。
3. 拡張が画像用チャットを開き、「画像を作成」を選択して1記事ずつ送信。画像取得後に次へ進む。「停止」で次の送信を止め、同じ開始ボタンで再開できる。
4. 「まとめてサイト保存」を押す。100件・80MBの送信制限を内部で自動分割する。日経マップを再読み込みする。

ZIP生成・画像生成APIは不要です。順次生成には「日経マップ Gemini画像取込」拡張1.4.1が必要です。既存登録フォルダはiCloud news1共通/gemini-map-import-extensionです。chrome://extensions の同名拡張の再読み込みを押して、抽出ツールも再読み込みしてください。権限・連携先は追加していません。

抽出ツールのタブを開いたまま実行してください。生成上限・拒否・ログイン切れ・10分のタイムアウトで停止します。制限の迂回や自動再送はしません。送信結果不明の場合はGeminiで確認が必要です。全記事が一度で生成できる保証はありません。閉じた生成タブは保存済みの会話URLから復元します。

自動生成は送信ごとの固有IDと元記事IDを保持し、対応する応答だけから画像を取り込みます。OCRや画像の並び順では判断しません。Geminiが説明を返さない場合は、画像を再生成せず説明だけ追加取得します。取得済み画像はIndexedDBに保存しますが、サイト共有は最後の「保存」が必要です。従来のURL・ファイル・ZIP取込は「設定・手動取込・画像の確認」に集約しています。

保存先は既存の日経マップのR2です。既存のサイト保存キーを使用します。記事・画像・説明は1つの公開インデックスで反映し、他の日付・面のデータは残します。保存エラー時は取り込んだ内容を保持します。

マスターはOneDrive news1共通/pdf-extractor-toolです（2026-10-13移行）。今回の変更前はnews1共通/バックアップ/20261010-bulk-extractor および 20261010-bulk-extension に保持しています。
